Checks whether a contract's signing domain actually works — the failure where a typo in the domain makes every signature it receives invalid. Just paste the address and press Inspect. Modern contracts publish their domain, so nothing else is needed.

Older tokens (USDC, DAI) expose their separator but publish no name, so there is nothing on-chain to compare against. If Inspect says cannot verify, add the name and version the token was deployed with — then it can be checked. A wrong name shows up as a mismatch, which is itself the answer.

The three things this checks

Will the contract accept your signature?
A wallet and a contract must agree on a domain string before signing. If a contract's copy has a typo, every signature it receives is invalid — forever, and silently. Nothing reverts. The wallet shows a normal prompt and the transaction simply fails.
What does the signature authorise?
A signature is not a payment. It is a standing permission. An unlimited allowance lets the recipient move your entire balance, not just what you meant to spend.
Can it be used against you later?
This is the one people miss. A permit does not have to be used immediately. If the permission has not been submitted yet, whoever holds it can use it whenever they like — and a deadline of the maximum number means never expires.

What your wallet already tells you

Modern wallets have improved. A prompt may already say "Spending cap: Unlimited" and name the spender. Where that happens, ClearSign is not repeating it — it adds the parts a wallet cannot know without asking the chain:

Whether the permit has been submitted yetNeeds to read nonces(owner)

What this cannot tell you

  • It is not a safety score. A malicious contract can ask for an unlimited approval with a perfectly valid domain. The signature verifies, and you are still drained. Only reading the fields catches that.
  • It checks EVM chains. Solana and similar have no standard typed-data signing, so there is nothing to compare — not unsupported, uncheckable.
  • "Cannot verify" is not a pass. When ClearSign cannot see enough to judge, it says so rather than implying the result is fine.

Where the contract address comes from

You do not have to go looking for it. When a site asks you to sign, the request it sends your wallet contains verifyingContract — the contract's address — and that is what your wallet displays in its prompt. Copying the request copies the address with it.

Real dapps usually gate the signing step behind eligibility — a balance, an allowlist, a mint window — so it can be surprisingly hard to reach a signature prompt on demand just to see what one looks like.

Nothing here moves funds. Signing typed data produces an off-chain signature; no transaction is sent and no gas is spent. But a signature is authorisation, so sign only what you understand. The examples point at example contracts. Use a wallet holding nothing you would miss.
