I only have a contract address, not a request

Checks whether a contract's signing domain actually works — the failure where a typo in the domain makes every signature it receives invalid. Just paste the address and press Inspect. Modern contracts publish their domain, so nothing else is needed.

Older tokens (USDC, DAI) expose their separator but publish no name, so there is nothing on-chain to compare against. If Inspect says cannot verify, add the name and version the token was deployed with — then it can be checked. A wrong name shows up as a mismatch, which is itself the answer.

ClearSign tells you three things about a signature request. That is the whole idea — everything else on this page is optional detail.

The three answers

Will the contract accept it?
If a contract's version of the signing string has a typo, every signature it receives is silently invalid. Nothing reverts — the transaction just fails, forever.
What does it authorize?
A signature is not a payment, it is a permission. Unlimited means the whole balance, not what you meant to spend.
Can it be used against you later?
A permission does not have to be used immediately. If it has not been submitted yet, whoever holds it can use it whenever they like — and it may never expire.

What your wallet already tells you

Where does the contract address come from?

You do not have to go looking for it. When a site asks you to sign, the request it sends your wallet contains verifyingContract — the contract's address — and that is what the wallet displays. Copying the request copies the address with it.

Habits that matter more than any single check

ClearSign helps with one moment: the second before you sign. These protect you the rest of the time, and they hold even when a check is fooled.

Keep a burner for anything new
A wallet holding nothing you would miss. Sign every first interaction with it, then move what survived. Most drains only take what the signing wallet holds.
Revoke regularly, not just after a scare
A permission keeps working whether or not you remember granting it. Revoking costs gas and a minute; a forgotten allowance can cost the balance.
One wallet per job
A wallet you only use for holding should never sign anything. If it never connects to a site, nothing can ask it for a permission.
Read the prompt, not the vibe
A clean-looking site behind a known brand tells you nothing — the front end can be cloned. What the wallet actually asks for cannot be faked.
Be suspicious of a chain prompt
"This site wants to add a network" is a common step in moving you onto a chain where the attacker's contract lives. ClearSign never asks you to add a chain.

None of this is a substitute for the check, and the check is no substitute for this.

What this cannot tell you
  • It is not a safety score. A malicious contract can ask for an unlimited approval with a perfectly valid domain. The signature verifies, and you are still drained. Only reading the fields catches that.
  • It checks EVM chains. Solana and similar have no standard typed-data signing, so there is nothing to compare — not unsupported, uncheckable.
  • "Cannot verify" is not a pass. When ClearSign cannot see enough to judge, it says so rather than implying the result is fine.

Real dapps usually gate the signing step behind eligibility — a balance, an allowlist, a mint window — so it can be surprisingly hard to reach a signature prompt on demand just to see what one looks like.

Nothing here moves funds. Signing typed data produces an off-chain signature; no transaction is sent and no gas is spent. But a signature is authorization, so sign only what you understand. The examples point at example contracts. Use a wallet holding nothing you would miss.
